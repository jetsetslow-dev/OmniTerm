# Bug fixes from the released build — 2026-11-13

Scope (user report against v0.9.296-main.1): App Lock asked for the PIN after an app switch inside a
60-minute window; Claude Code and Codex screens showed blank cells and garbled text until the
keyboard was hidden, also in new sessions and while scrolling; editor highlighting. Branch
`fix-app-lock-and-terminal-repaint` from main after #150. The private investigation is in the
internal docs as `BUG_INVESTIGATION_2026-11-13.md` (A–C; D, a Markdown preview, is not in scope).
Review and merge remain the user's.

- **App Lock** (59c3360): the window was per ViewModel and in memory, so any new process or rebuilt
  screen locked. It is now process-wide and, when left unlocked, kept in a small private record
  (boot count, time since boot, process id, install time; no secret, never backed up). A new
  process takes it over only for the same boot and install, inside the timeout, and when Android
  closed the previous process itself; force stop, crash, ANR, update, reboot, Android 10 and older
  lock. "Lock now" added. Editor buffers survive a relock. Device: 10-minute window kept across an
  app switch and a background kill at 9:30, locked at 10:30 and after a reboot.
  The PR's first CI run failed one window test (a follow-up commit fixes it): when the database
  answered the start-up read before the settings collector saw its empty placeholder, the
  placeholder then read App Lock (and battery saver) as off until the next emission, so leaving
  that screen opened no window. Locally the read never won that race. The collector now ignores
  the placeholder; a test with a database that answers at once fails without that (on App Lock, and
  on battery saver alone) and passes with it.
- **Terminal pipeline** (7628473): one publisher per session replaces the 16 ms throttle whose race
  dropped a burst's last update (B1); a new session opens at its emulator's size and the first
  measure of its pane is not skipped (B4); the viewport is one value read once per publish (B5); a
  resize during a reconnect reaches the new channel (B6).
- **Terminal emulator** (ac6032d): widths from Unicode 16 (B2), generated by
  `scripts/generate-unicode-width.py` (pinned files, SHA-256, `--check`); the parser reads and
  ignores sequences it does not implement and gains DEC line drawing, REP, autowrap/insert/origin
  modes, tab stops, colon SGR, strike-through and concealed text, xterm scroll-region and DECSC
  semantics (B3). TERMINAL_COMPATIBILITY.md, NOTICE (Unicode licence) and README updated.
- **Editor** (015fc58): stateful line lexer for shell and YAML (multi-line strings, heredocs, block
  scalars), quote and keyword boundaries, CRLF and tab keys, more file names and shebangs, per-line
  cache; the gutter is drawn from the field's layout (C1–C6, C8). No new languages.
- **Dependencies** (d6d9d50, and a follow-up commit): Roborazzi 1.79.0; then Robolectric 4.18, KSP
  2.3.14 and actions/setup-java 6.3.0, released during review; checksums written and verified.
- Proof: every new JVM test fails on the code before its fix (old throttle 2/5, old sizing 1/1, old
  emulator 28/33, old highlighter 8/8, fixed-height gutter 1/9). On the API 35 emulator against the
  repo's SSH fixture, before → after: bursts whose last update stayed off screen 4/400 → 0/400 (and
  0/400 → 0/400 with all four cores busy); ✅ 1 → 2 cells, 🖥 2 → 1, `ESC ( 0 lqk` `lqk` → `┌─┐`,
  DECRQM printed `p` → nothing, modifyOtherKeys dimmed text → not; editor line 60's number beside
  line 83 → beside line 60. 50,000 lines: median 1.63 s before, 1.68 s after over nine runs each,
  ranges overlapping; the parser alone is unchanged on the JVM (158 → 151 ms for 3 MB).

## Checkpoint C2 — phone-side ping, TCP and DNS checks (c24f0e9)

- Three more `EndpointChecks` kinds, each timing a reply in ms (below zero on failure), giving up
  after 3 s (`QUICK_TIMEOUT_MS`), checked every poll but at most once a minute, like URL checks:
  - Ping: one `-c 1 -W 3` through `/system/bin/ping` (`ANDROID_PING_BINARY`, now in the data
    package). Blank target = the host's own address. A watchdog thread ends a ping that hangs past
    the limit: the timed `Process.waitFor` needs API 26 and the app supports 24 (lint caught it).

    query id.

  strips IPv6 brackets. Tools → Ping and Traceroute used to accept `-f` and similar; they now use it.

  the share probe and Host Scan's port probe. `serializeDnsQuery` moved to `data/DnsWire.kt` and

  `hostAndPort` is shared by the TLS, TCP and DNS targets.
- Editor: the chips, defaults (Ping 200 ms, TCP 1000 ms, DNS 500 ms), labels, examples and hints;

## Checkpoint C3 — opt-in alert forwarding (dd92901)

- `data/AlertForwarding`: Off (the default), an ntfy topic (ntfy.sh or the user's server, optional
  access token), a Gotify server (application token) or any webhook (optional bearer token).

  stay out of HTTP headers), Gotify's `/message` with `X-Gotify-Key`, and a webhook object with
  source, event (triggered or resolved), severity, host, rule, title, message, value, threshold and

- `send()` never follows a redirect (that would take the token to an address the user did not enter;

  posted) and an incident resolving. A muted incident's recovery is not forwarded; the alerts switch

  forwarded again.
- Settings: `alert_forward_*`; the token is in `secureSettingKeys`, so it is stored with the

## Checkpoint D1 — Tasker and other apps run a saved script (d1c5483)

- Tools → Automation, off by default (`automation_enabled`). A token runs one saved script on the
  hosts picked for it: `omt_` plus 128 random bits, shown once, stored only as its SHA-256 in
  `automation_grants` (schema v27, `MIGRATION_26_27`), revoked from the list. Making one asks for
  App Lock, else the phone's screen lock, else a plain confirmation (`SensitiveActionDialog`, now
  shared with sudo; `AppLockAuthDialog` is the one App Lock dialog, also used by Settings' Save).
  The token is copied as sensitive text and cleared from the clipboard after a minute on the app's
  scope. The switch joins `DEVICE_LOCAL_SETTINGS` (one list, used by export and restore), so a
  backup never carries it either way; grants are never in a backup.
- Ways in, both exported, both deciding only by the token: the Locale/Tasker plug-in
  (`TaskerEditActivity` for EDIT_SETTING, `TaskerFireReceiver` for FIRE_SETTING) and the
  `com.jetsetslow.omniterm.action.RUN_SCRIPT` broadcast (`AutomationReceiver`) with an optional
  reply to one named package and action. The edit screen makes nothing: it checks a pasted token,
  shows the script, hosts and the calling app, and saves only for an app waiting for a result
  (with REQUESTED_TIMEOUT and the relevant variables when the host supports them). An unknown
  token gets no answer; a known one always goes to the job, which answers "automation is off" too.
  Tasker gets result code 3 (pending), then its completion intent (which must name an app; its
  selector is dropped) with `%output`, `%exit`, `%failed_hosts` and `%errmsg` on failure.
- The run is a JobScheduler job (expedited on Android 12+, where a broadcast may not start a
  foreground service; a plain job when Android refuses that). `AutomationRunner` probes each
  host's OS, skips hosts whose script names another OS, fills `{{value}}` defaults for the host's
  shell, runs built-in presets in the app's own form and anything else in the login shell, runs 8
  hosts at once, gives up after 9 minutes (exit 124; unreachable is 255), and records the run in
  Fleet's history as `automation`. Unknown host keys are refused (no one to approve them). Shared
  rather than copied: `HostCredentials` (credentials for screens and jobs), `UnattendedScripts`
  (Script Check's refusals, worded for each), `builtInPresetCommandFor`, `sshCommandExit` /
  `sshCommandOutput`, `FleetRunHistory.host`.
- Protocol facts are from Tasker's plug-in page and the Locale spec (Apache-2.0); Tasker's own
  TaskerPlugin.java states no licence, so nothing is copied. Departure: Locale says not to put
  credentials in the bundle; the token is the credential, scoped to one script and revocable, and
  the README says Tasker's exports contain it. The `<queries>` entry makes Tasker visible so its
  completion intent is delivered.
- Credit (README): Termux:Tasker and Home Assistant for Android; Tasker's docs and the Locale spec.
- Tests: `AutomationRobolectricTest` (11: token shape and hash, ids, OS skip, result, variables,
  bundle, completion intent, reply, job extras), `AutomationRunnerRobolectricTest` (10: runs and

## Cloudflare Access service-token SSH (Nov 14, Codex relay lane)

Protocol research: [cloudflared](https://github.com/cloudflare/cloudflared), Apache-2.0, revision
`b0297f0b24c60a4cef743b7b878e2da3798cb839`, read as a reference, reimplemented without copying code.
- [`cmd/cloudflared/access/carrier.go`](https://github.com/cloudflare/cloudflared/blob/b0297f0b24c60a4cef743b7b878e2da3798cb839/cmd/cloudflared/access/carrier.go), `ssh` / `StartForwarder`: uses the application's URL, service-token headers `CF-Access-Client-Id` and `CF-Access-Client-Secret`, and its own User-Agent. The optional `--destination` uses `Cf-Access-Jump-Destination` for bastion mode; OmniTerm does not implement that mode or send that header. OmniTerm identifies itself with User-Agent OmniTerm.
- [`carrier/websocket.go`](https://github.com/cloudflare/cloudflared/blob/b0297f0b24c60a4cef743b7b878e2da3798cb839/carrier/websocket.go), `createWebsocketStream`, `websocketHeaders`, `clientConnect`: HTTP GET to the application with HTTPS switched to WSS for Gorilla. The library supplies Connection/Upgrade, Sec-WebSocket-Key and Version; no subprotocol or compression is requested. Successful upgrade is HTTP 101. OmniTerm uses the same wire contract at HTTPS:443 `/`, with coder/websocket.
- [`carrier/carrier.go`](https://github.com/cloudflare/cloudflared/blob/b0297f0b24c60a4cef743b7b878e2da3798cb839/carrier/carrier.go), `IsAccessResponse` identifies HTTP 302 whose Location path begins `/cdn-cgi/access/login`. Cloudflared then obtains app information and an interactive JWT (`Cf-Access-Token`) and may retry; OmniTerm instead explains that Service Auth is required and stops. HTTP 401/403 is presented as a token/policy rejection (it cannot distinguish revoked/expired credentials from policy refusal). Non-upgrading 200/404 or unrelated redirects say the hostname is not accepting Access TCP; 429/5xx and network/TLS failures say Cloudflare is unreachable. Server bodies and redirect queries never reach diagnostics.

## Release packaging: one APK per architecture, no 32-bit x86 (Nov 16)

The tunnel libraries made the app large: the tunnel AAR was 40.5 MB and the universal APK carried
a 25 to 28 MB native library for each of four architectures. The owner kept every tunnel kind and

- GitHub releases publish one open-source APK per architecture next to the universal APK, which
  keeps the name the single APK always had: `OmniTerm-OpenSource-<tag>.apk` and
  `OmniTerm-OpenSource-<tag>-arm64-v8a.apk`, `-armeabi-v7a.apk`, `-x86_64.apk`. The release build

  getting tunnels that cannot load (`libandroidx.graphics.path.so` had an x86 copy too). The Play

  bundle's (AGP's default for splits; nothing overrides it). Per-architecture offsets exist for
  uploading several APKs to Play, which gets only the bundle here; the APKs are another package
