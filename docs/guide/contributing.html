Contributing

Contributions are welcome. The authoritative rules are in CONTRIBUTING.md; by contributing you agree that your contribution is licensed under the GPL-3.0 and that the project owner may also license it under other terms (see Licence).

Workflow

  1. Branch from main with a descriptive name.
  2. Keep changes focused and add regression tests for behaviour changes.
  3. Run the smallest relevant tests, then the repository gate (see Building from source).
  4. Open a pull request that explains the user-visible behaviour, risks and test evidence, with screenshots for UI changes.

Pull requests must pass build and tests, lint, dependency review, secret guards and CodeQL where applicable. Never commit credentials, keystores, service-account files, host inventories or terminal output containing secrets; use synthetic fixtures.

Terminal changes

Terminal behaviour is stateful and timing-sensitive. Include tests for chunk boundaries, malformed input, resize during alternate-screen use, reconnect and close races, UTF-8 and tmux control-mode framing, and update the compatibility matrix when support changes.
