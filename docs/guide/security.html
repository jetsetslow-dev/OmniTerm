Security and privacy

The full policy is PRIVACY.md; this page summarises it.

What stays on the device

Hosts, credentials, keys, scripts, alert rules, history and settings are stored locally. Credentials, private keys, sudo and proxy passwords are encrypted with AES-GCM using an Android Keystore key (hardware-backed where the device supports it). OmniTerm runs no backend for telemetry, analytics, advertising, crash reporting or credential sync.

Where traffic goes

Directly from the phone to the hosts and proxies you configure, or through a VPN tunnel you chose for a host. The exceptions are those you turn on: alert forwarding to the address you enter, automation results to the app that asked, and MCP answers to the assistant presenting its token. The Play Store build also contacts Google for ads, consent and billing; the open-source build has no ad SDK.

Protections

  • SSH host-key pinning; a changed key is rejected until reviewed.
  • Optional App Lock with biometrics or PIN. Cold starts always lock.
  • Everything that runs with sudo asks first, every time (App Lock, the phone's screen lock, or a plain confirmation on a phone without one).
  • FIDO2 security keys and SSH certificates; agent forwarding off by default.
  • Opt-in automation and MCP with tokens that are shown once and stored only as fingerprints.
  • AES-256-GCM encrypted backups.
  • Permissions are limited to visible features; no storage permission or All Files Access. File import and export use Android's document picker.

Reporting a vulnerability

Do not open a public issue. Use GitHub's private reporting; the security policy lists response times and scope. Only the latest release receives security fixes.
