Troubleshooting and FAQ

Common problems

Host shows offline
Check the hostname or IP, SSH port, network route and firewalls.
Authentication fails
Verify the user name, password or key, and any proxy or jump host.
"Connection dropped during handshake"
The server closed the connection before sign-in. It may still be starting, or (OpenSSH 9.8 and later) it is turning your device away for a while after several failed sign-ins. Wait a minute and retry.
"This host signs in with a security key"
Open a terminal to it and touch the key; its checks then use that sign-in.
"This host asks a sign-in question"
The host uses two-step sign-in. Open a terminal and enter the current code.
Monitoring is empty
Confirm the host has the expected platform tools. Windows hosts need OpenSSH Server and Windows PowerShell.
Containers tab is empty
Confirm Docker or Podman is installed and the SSH user may run it.
Kubernetes tab fails
Run kubectl get pods as the SSH user on the host; the tab sees what that command sees.
A port-forward tunnel will not start
Confirm the bind port is free and the destination is reachable from the SSH host (-L) or from the phone (-R).

FAQ

Do I need an OmniTerm account?
No. There is no OmniTerm cloud service.
Do I install anything on my servers?
No. OmniTerm uses SSH and each host's own tools.
Do the two builds differ in features?
No. They differ in distribution and in the Play Store build's host limit and ads. See Getting started.
Does an AI assistant see my passwords?
No. MCP is off by default, shows only hosts you tick, never gives credentials or addresses, and every run needs your approval on the phone.

Getting help

Search existing issues, then use Discussions for questions or an issue template for a reproducible bug. Attach the diagnostics from Tools → About OmniTerm → Device & diagnostics after removing host names, addresses and secrets. Support is best-effort.
