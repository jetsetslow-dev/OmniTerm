Monitoring and alerts

Live monitoring

Monitor shows CPU, memory, disk, load, uptime, temperature, per-core usage, network and disk I/O, SMART health, and process, service, log and cron views. Metrics come from each host's own tools, so there is no agent. Services are managed through systemd, OpenRC, rc.d, rcctl, launchd or Windows services as appropriate.

Specs

The Specs tab lists hardware and software for Linux, FreeBSD, macOS and Windows hosts. Details that need administrator rights are read only when you tap Read with sudo. Where a helper program such as dmidecode or smartmontools is missing, an Install button uses the host's package manager after you authenticate.

Alert rules

  • Usage: CPU, memory, disk and latency thresholds.
  • Checks the phone runs itself: TLS expiry, URL, ping, TCP port and DNS, about once a minute, so they work when a host has no SSH. Checks of a host that uses a VPN tunnel go through it where supported.
  • Host state: Host Offline, Failed Services, Container Problems, Storage Health (ZFS, mdadm, SMART), ZFS Scrub Age, UPS On Battery and Reboot Required.
  • Script checks: run one of your saved scripts on the host and alert on a non-zero exit. Destructive-looking scripts are refused.
  • Runbooks: a rule can name a saved script; its notification offers a Run button that opens Fleet and asks for confirmation first.

Checks run from the phone while OmniTerm is running.

Alert forwarding

Off unless you set it up. Alerts can be sent to an ntfy topic, a Gotify server or any webhook you name, with Send test before you save. Only the alert's title and text go out. A plain http:// address sends in clear text and the form says so.

Network tools

Host scan, Wake-on-LAN, ping, traceroute, port scanner, DNS lookup, WHOIS, speed test and SSH port-forward tunnels (local, remote and SOCKS).
