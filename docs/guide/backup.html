Backup and restore

Under Tools → App backup, export or restore a selective backup. Every section is ticked unless you untick it, except crash logs.

What it can contain

Hosts (with their VPN tunnels, Telnet connections, Kubernetes clusters, tmux sessions and Compose stacks), SSH keys, credential profiles, scripts, alert data, saved shares, settings including App Lock, Fleet history, monitoring history, the AI assistant log, and automation tokens with the AI assistant's settings. Backups never copy files from your remote hosts.

Protection

  • Backups with sensitive sections are encrypted with AES-256-GCM using a key derived from your passphrase. OmniTerm does not store the passphrase; keep it safe.
  • A backup that includes hosts is always encrypted, because it carries tunnel private keys.
  • Android's own auto-backup is disabled for this app.

Restoring

  • Restoring adds what the phone does not have, so restoring the same backup twice changes nothing.
  • Automation and the AI assistant come back off; turn them on when you are ready.
  • The backup's App Lock PIN replaces the phone's, so know that PIN. A backup made with the lock off never turns the phone's lock off. Fingerprint unlock is per phone.
  • A restored host whose tunnel was not in the backup stays unreachable until you pick a tunnel or None; it never connects directly by itself.
  • A backup over about 12 MB compressed is not saved; untick Monitoring history or Fleet history.
