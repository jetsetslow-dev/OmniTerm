Containers

Docker and Podman

Under Containers, containers, stacks, images and volumes are listed for the selected host; Docker and Podman are detected automatically. Each container offers logs, live stats (CPU, memory, network, block I/O), an exec shell and start, stop, restart and pause. Stacks run by Docker Compose or podman-compose have full lifecycle actions.

Compose Builder

A visual editor for docker-compose.yml. It keeps the file's own style and comments, updates every reference when you rename a service, flags what Compose would refuse (missing dependencies, loops, undeclared volumes or networks, duplicate container names) and validates with compose config before a deploy.

Kubernetes

Open Containers → Kubernetes on a host with kubectl, k3s or MicroK8s, or import a kubeconfig to talk to a cluster directly. Pods offer logs, follow, previous logs, shell, describe and delete; deployments offer scale, restart and describe; services and nodes can be described; nodes can be cordoned. Clusters whose credentials come from a program such as aws or gcloud cannot be used, and the import says so.

Container management needs a Linux, macOS or BSD host; Windows hosts say so instead of failing.
